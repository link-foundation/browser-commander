## Bugs in the templates themselves (to report upstream)

1. **rust template, redundant doc-test step.** `/tmp/tpl/rust/.github/workflows/release.yml:535-547` runs `cargo test --all-features --verbose` and then `cargo test --doc --verbose`.
   - The first command already runs the lib doctests.
   - The second, run without `--all-features`, changes the feature set. In any downstream crate that declares features, the crate is recompiled (proved in `/tmp/repro128/doccrate`).
   - In browser-commander this cost a red main build: Windows took more than 180s and exited 124 (`ci-logs/rust-37509328352.log:8788-8791`).
   - Fix: remove the step, or pass `--all-features`.
2. **rust template budget wrapper, misleading comment.** `/tmp/tpl/rust/scripts/run-with-budget-warning.sh:70-71` claims "A root command that exits while a worker survives therefore cannot fake completion".
   - But `command_is_running` returns "done" as soon as the status file exists, so the wrapper still exits 0 with live group members.
   - Only the pipe-hang half of rust#172 is fixed, and nothing reports the survivors on the success path.
   - Fix: after completion, call `report_survivors` (or fail) when `group_members` is non-empty.
3. **rust template, runner labels.** It still uses `ubuntu-latest` 34 times. js#193 and py#89 pinned `ubuntu-24.04`, but there is no rust equivalent, and the Ubuntu 26 migration starts on 2026-10-19.
4. **js template, inconsistent zizmor versions.** `/tmp/tpl/js/.github/workflows/workflows.yml:116` pins the action at `version: 1.29.0`, while line 130 runs `pipx run zizmor==1.30.0`. One audit job uses two zizmor versions.
5. **rust template, unpinned secretlint.** `/tmp/tpl/rust/.github/workflows/release.yml:241` uses `npx --yes -p secretlint ...` with no version. That is the adhoc-package pattern that zizmor flags elsewhere in the templates, and it contradicts the templates' own pinning principle.

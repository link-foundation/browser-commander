The classes are not independent here, and that is the central finding of this
issue. **RC-B is a false negative that manufactures errors**: because
`command-stream`'s `$` resolves rather than rejects on a non-zero exit, every
`try { await $\`…\` } catch { process.exit(1) }`in thirteen release scripts is
dead code. That single defect is why RC-C and RC-G both shipped green. And
**RC-E is a false negative that manufactures a false positive**: the release
commit is pushed with`GITHUB_TOKEN`, which by design triggers no workflows, so
a formatting violation introduced by the release lands on main untested and
detonates on somebody else's pull request.

## G. The warnings audit (R-8)

Every warning emitted by the eight runs named in the issue, grepped out of the archived
logs in `../logs/`. None is a defect in this repository, and recording that is the point:
an audit that finds nothing has to say so, or the next reader repeats it.

| Warning                                                  | Where                              | Verdict                                                                                                                                                                                         |
| -------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm warn deprecated prebuild-install@7.1.3`             | every `npm ci`                     | upstream and transitive, via `better-sqlite3`. Not reachable from here; no direct dependency to move                                                                                            |
| `npm warn install-scripts … blocked`                     | every `npm ci --ignore-scripts`    | the intended consequence of `--ignore-scripts`, which is the safe default. The one package that genuinely needs its build step, `better-sqlite3`, is built explicitly by the step that needs it |
| `DeprecationWarning: Buffer() is deprecated` (`DEP0005`) | inside `actions/download-artifact` | in GitHub's own action, not in any code here                                                                                                                                                    |
| `Codecov: token not found` (notice, not a warning)       | `coverage` jobs                    | deliberate — `CODECOV_TOKEN` is unset, and public-repository uploads work without it. Downgrading a green run for a notice would be the false positive this issue exists to remove              |

No `cargo` warnings and no `ruff`/`mypy` warnings appear in any of the eight runs. The
ten ESLint warnings in `scripts/` that issue #81 noted are unchanged and remain out of
scope: `lint-changed-lines.mjs`, the template's answer to them, narrows what a run
reports, which is the opposite direction from "find every warning".
